# Stage 1: LeWM 学習 + 潜在空間の診断

## 目的

Stage 0 で推定した低固有次元 (~6) が, LeWM の学習後にも潜在空間の構造的問題として現れるかを検証する. 具体的には, 学習中の encoder 出力の有効ランク (RankMe) を追跡し, SIGReg が未使用次元にノイズを注入しているかを直接観測する.

## 実験設定

| 項目 | 値 |
|---|---|
| データセット | `lerobot/berkeley_autolab_ur5` (1,000 エピソード, 97,939 フレーム) |
| モデル | LeWM デフォルト設定 |
| エンコーダ | ViT-tiny (192 次元埋め込み, patch 14, image 224) |
| プレディクタ | Transformer (depth 6, 16 heads, MLP 2048) |
| SIGReg | weight=0.09, knots=17, num_proj=1024 |
| 学習 | 5 エポック, batch_size=128, lr=5e-5, AdamW, bf16 |
| ハードウェア | RTX 5090, 所要時間 ~58 分 |
| 診断 | validation 時に encoder 出力の SVD → 有効ランク, 特異値スペクトルをエポック毎に記録 |
| スクリプト | `scripts/train_lewm_diagnostics.py` |

有効ランク (RankMe) は特異値の正規化エントロピーの指数関数で定義される: $\text{eff\_rank} = \exp(-\sum p_i \log p_i)$, ここで $p_i = \sigma_i / \sum \sigma_j$. 全次元が均等に使われていれば 192, 1 次元に集中すれば 1 に近づく.

## 解釈

### 1. SIGReg ミスマッチの確認

有効ランク ~52 は, データが本来必要とする次元数 (Stage 0 推定 ~6–12) より大きいが, 潜在空間の次元 (192) より大幅に小さい. これは以下のメカニズムを示唆する:

- SIGReg は全 192 次元を等方ガウスに近づけようとする
- しかしデータの構造は ~50 次元程度にしか意味のある変動を持たない
- 残り ~140 次元では, SIGReg がノイズを注入して分散を確保している
- このノイズは予測に無関係であり, プレディクタが信号とノイズを分離する負担を増やす

### 2. 損失のバランス異常

SIGReg/pred 損失比が ~183 (エポック 4) であることは, 学習全体の勾配がほぼ SIGReg に支配されていることを意味する. weight=0.09 を乗じても, 総損失に占める SIGReg の寄与は:

$$\frac{0.09 \times 2.37}{0.09 \times 2.37 + 0.013} = \frac{0.213}{0.226} = 94\%$$

つまりエポック 4 でも総損失の 94% が SIGReg 由来. エンコーダの学習は"予測に有用な表現を作る"よりも"全次元を均等に使う"ことに駆動されている.

### 3. Stage 0 との関係

| 測定タイミング | 手法 | 推定次元数 |
|---|---|---|
| 学習前 (Stage 0) | Two-NN (ViT 空間) | ~6 |
| 学習前 (Stage 0) | PCA 95% (ViT 空間) | 12 |
| 学習後 (Stage 1) | 有効ランク (RankMe) | ~52 |

学習前の固有次元 (~6) は学習後の有効ランク (~52) を大幅に下回る. これは学習によりエンコーダが非線形な特徴空間を構築し, より多くの次元に情報を分散させた結果と解釈できる. ただし, SIGReg の等方化圧力も有効ランクを人為的に引き上げている可能性があり,"情報を持つ次元"と"SIGReg に膨らまされた次元"の区別は特異値スペクトルだけでは困難.

### 4. TwoRoom との類似性

LeWM 論文で報告された TwoRoom の症状 (固有次元 ~2, 有効ランク << 192, SIGReg が品質を劣化) と構造的に同じパターンが UR5 画像データでも観測された. 乖離の程度は TwoRoom (~96 倍) より穏やか (~32 倍) だが, 損失のバランス異常と有効ランクの飽和は共通している.

## 判断

**SIGReg ミスマッチは UR5 データでも発生している.** 有効ランク ~52/192, SIGReg が総損失の 94% を占める状態は, エンコーダが予測タスクに最適化されるのを阻害している可能性が高い.

次のステップとして:

1. **Stage 2**: multi-step 予測精度を測定し, この構造的問題が下流の予測性能にどう影響するかを定量化する
2. **RoboMIND UR5e**: より大規模なデータ (25K 軌跡) で同一実験を再現し, データ量の効果を確認する
